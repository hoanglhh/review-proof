# Decision log

Short, dated entries. Newest last.

## Seeded from the design brief (2026-11-14)

- **No numeric risk score.** Tieto rejects scores nobody can explain, and a weighted sum lets one critical factor be averaged away. Review depth comes from fixed rules that name their reasons.
- **The reviewer cannot approve.** No command, flag or default creates a sign-off; only a named human submitting the form does.
- **Tieto's four branches instead of invented pull requests.** Real agent-written changes to a real library, each pinned to a commit.
- **Command line plus static page instead of a web application.** One person must build and explain it; JSON files are the interface between stages.
- **.NET runs only in the repository's pinned container** (`mcr.microsoft.com/dotnet/sdk:8.0.402-jammy`), never installed on the host. The agent's code is untrusted.
- **Four claim states, no percentages:** `proven`, `argued`, `not_checked`, `broken`, computed by code from evidence records.
- **The scoring key is kept from the reviewer.** It lives in `labels/`, which the reviewer module never reads.

## Build decisions

- **2026-11-14: TypeScript run directly by Node 26 (type stripping), no build step.** One runtime dependency (`zod`, for validating reports and model output). Fewer moving parts to explain.
- **2026-11-14: Run the whole affected test project three times** (head; base; base source with the head's test files) instead of filtering by test name. New tests are found from the results (present at head, absent at base), so the pipeline does not need to parse test code. Known limit: a test whose code was edited but whose outcome did not move is not identified as changed.
- **2026-11-14: Every check states its assertion, and `passed`/`failed` refer to that assertion.** Example: `public-surface` asserts "no public declaration, API entry or diagnostic ID changed", so `failed` means "public surface changed, a human must own it", not "the change is wrong". This keeps four statuses without inventing new ones.
- **2026-11-14: Zero-context hunks (`git diff -U0`) are the unit** for claims, unexplained code, the reading list and the read ratio, because they count exactly the changed lines.
- **2026-11-14: Repository-specific facts live only in `profiles/<name>.json`**, including the test-result format (`trx`), which selects a parser. A unit test fails if corpus names appear in `src/`.
- **2026-11-14: Commits.** Committed locally after each build step on branch `reviewproof-build`, never pushed (user's choice).
- **2026-11-14: Reviewer adapter is plain `fetch` to an OpenAI-compatible endpoint** (Verda, model from `.env`), no SDK. Tested before relying on it: with a strict `json_schema`, the endpoint dropped a `confidence` field the prompt asked for; in plain JSON mode it added one. Output is also validated with zod; extra fields make it invalid, and invalid means blocked.
- **2026-11-14: `.env` is read into a local object, never into `process.env`,** so the key cannot reach the container that runs the agent's code.
- **2026-11-14: Citation quotes are compared with whitespace runs collapsed,** and must be at least 8 characters. A finding with no resolvable citation is dropped. A decision keeps its place (it is a question for the owner, not evidence) but loses any citation that does not resolve.
- **2026-11-14: Only test runs, `existing-tests` and `issue-reproduction` can support a claim.** Inventory, pattern groups, public surface and security scan are routing checks: they decide how much to read, never whether a claim holds.
- **2026-11-14: A pre-existing test that passes at base and head makes a linked claim `proven`** (as section 5.5 says), and the reason text states that this shows behaviour kept, not that the change adds any. Risk: the model links an irrelevant old test. Watch for it in the failure log.
- **2026-11-14: Prompt v1 is generic:** no case-specific hints or examples. The builder had read the scoring key (it is in the design brief), so example decisions that resembled it were deliberately left out of the prompt. No prompt iterations yet.
- **2026-11-14: Evidence trimming fix (prompt v1 → v2).** Reading the built prompt for #2283 showed that test failure output reached the model cut short: stored messages were capped at 4,000 characters, and the trim kept the first 12 matching lines, which stack-trace frames used up. The base run's diagnostics after the crash were lost. Fix: cap raised to 20,000 characters, stack frames dropped, up to 30 lines kept. Decided after reading the prompt and **before** reading v1's output. Both raw responses are kept under `data/cases/2283/review/`. Recall before and after can be scored once the user confirms the scoring key.
- **2026-11-14: The sign-off server is the only writer of human records.** Sign-offs, interpretation confirmations, spot-checks and trust events are written only by POST handlers in `src/server.ts`, each as a new file (opened with `wx`, so nothing is overwritten); reports are never rewritten by a sign-off. A unit test fails if another module writes sign-offs or a command named `sign…` appears.
- **2026-11-14: The server is local-only and refuses foreign posts.** It binds to 127.0.0.1, checks the `Host` header (DNS rebinding) and the `Origin` of every POST (another website cannot submit a sign-off from the owner's browser), forbids framing, and serves logs as plain text because they contain agent output.
- **2026-11-14: Interpretation confirmations are matched by the requirement quote,** so a confirmation survives a regenerated review that renumbers requirement items. Confirming re-assembles the report; the owner then reviews the new version (the page hash changes, so an old page cannot be signed).
- **2026-11-14: How an area starts a track record.** The random spot-check draw applies only to reports whose effective route is not full, and every area starts at full, so the draw alone would never start a record. A blind spot-check can therefore be opened from any sheet: while an area is at full read the owner reads everything anyway, and doing that read blind costs nothing extra. A clean blind read counts for every area the change touches; a miss counts against the area the reader names. Informed reads are saved but kept out of the record.
- **2026-11-14: Active review time is measured by the page** (seconds visible and focused) and submitted with the form; the record says so, because the browser reports it.
- **2026-11-14: Success paths of confirm, sign and spot-check were tested on a throwaway copy in `/tmp`** with a synthetic name. The real `data/` has no confirmation, sign-off or trust event: those are the owner's actions.
- **2026-11-14: Large changes are shown to the reviewer as one exemplar per repeated-pattern group** plus every hunk outside a group. The model may name a group (`G1`) instead of each hunk; assembly expands it. The report lists which files were represented rather than shown. For #2297 this shows 20 of 423 hunks.
- **2026-11-14: Pattern groups use exact matching after trimming whitespace.** On #2297 this finds 402 identical hunks in 222 snapshot files and two deviating snapshot files: one with a moved brace, one with an extra blank line. The brief's unverified note expected one. Exact matching was kept: a blank line is a real difference in generated output.
- **2026-11-14: Planted bugs are deterministic local commits** (fixed author and date) on top of a case's head, on no branch, never pushed. A plant reuses its original case's saved requirement and base-commit test run, because the commit is the same.
- **2026-11-14: "Caught by a run" means a run check that passed on the original change no longer passes with the plant, or a claim became broken.** "Caught by the model only" means a finding or a model-raised decision points at a planted hunk or line. When the reviewer has not run, an uncaught plant is reported as `model_not_run`, never as `missed`.
- **2026-11-14: The AI review of #2234, #2129, #2297 and of the plants waits for a funded API key.** Everything else ran. Their sheets are blocked with reason `reviewer-missing` until then.
- **2026-11-14: Owners can mark each finding as a real problem, not a problem, or not sure when signing** (optional), so "findings marked real" can be measured.
- **2026-11-14: Calibration, run phase (no model): 7 of 8 plants caught by a run, 0 missed, 1 waiting for the model.** The plant `untested-private-ctor` was meant to be a change no test exercises (no test names its diagnostic, MsgPack013), but 4 existing tests regressed, so a run caught it. That leaves `template-source-drift` as the only plant in the "tests do not exercise it" category. The security plant was caught three ways: the security scan, the repository's own analyzer ban on file access (RS1035, the build failed), and the head tests not running as a result. Plants that undo part of the change leave no new hunk, so their location is the place where the agent's hunk used to be.
- **2026-11-14: A linked pre-existing test no longer makes a claim `proven`; it makes it `argued`.** This reverses the earlier entry that followed section 5.5's wording. On #2234 the model linked an unrelated old test to a claim (failure mode 6). Section 2's definition wins: `proven` needs a check shown able to fail, and an old test passing at both commits never was, for that claim. No route changed: #2234 was already blocked.
- **2026-11-14: In calibration, the model is called only for plants no run caught,** because a model finding cannot change the outcome of a plant a run already caught. One call instead of eight.
- **2026-11-14: Whole records never prove a claim; only a named discriminating test does.** After the change above, #2234's C7 was still `proven`, now through the linked `existing-tests` record ("167 pass at both"). The same holds for `issue-reproduction`. Which claim a whole record bears on is the model's word, so these records can make a linked claim `broken` (a regression) but not `proven`. This supersedes the step-3 entry that let `existing-tests` and `issue-reproduction` support claims. Both stay on the sheet as evidence for the owner.
- **2026-11-14: Calibration, final: caught by a run 7 of 8, caught by the model only 0 of 8, missed 1 of 8.** The one miss is scored by the rule written before the run, even though the reviewer's finding F1 describes the planted problem (failure mode 7). Changing the scoring rule after seeing the result would make the number meaningless.
- **2026-11-14: Final calibration outcomes are appended to the real trust record** as `planted_caught` / `planted_missed`, marked synthetic, once per plant. A miss resets the area it touched (`generator-templates`); a catch changes nothing.
- **2026-11-14: The reading list reads a repeated-pattern group once, through its exemplar.** Before this, a decision citing group G1 put all 402 identical snapshot hunks of #2297 on the reading list (1390 of 1392 lines), which defeats grouping. Now: 183 of 1392 lines. This completes the design in the brief (grouping tells the person which files are identical; deviating files stay listed) and changed no route.

All four changes are blocked on unconfirmed interpretations; without this line, #2129's forced full read and #2297's targeted read would not be visible.
